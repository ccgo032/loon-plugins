# 脱敏分析和验证记录

日期：2026-11-03。抓包中出现的喜马拉雅版本：9.5.22；广告 SDK 请求的 User-Agent 以 `ting/9.5.22.6` 开头。

本记录只保留公共接口、字段名称和汇总统计。原始抓包、账号信息、设备标识、Cookie、Token、完整请求头、带参数的原始 URL 均未进入仓库。测试夹具独立手写，不是原始抓包响应。

## 抓包中的直接证据

- 共分析 173 条请求。9 条记录存在旧规则生成的替换响应，因此不能把仍有开屏广告简单归因为“所有复写都没有开启”。
- `GET mobwsa.ximalaya.com/mobile-resource-position/resource/advertising/free/v2` 的成功响应中，`data.isAdShow` 为布尔值 `true`；该条记录没有旧规则的替换响应。
- `tmeadkg.y.qq.com` 下发现 2 条 `POST /maproxy/getAd` 和 8 条 `POST /maproxy/getPbCompressAd`。这些广告获取请求没有旧规则的替换响应；User-Agent 都以 `ting/` 开头。
- 两条 JSON 广告请求包含冷/热启动和开屏相关字段，但其返回的广告列表已经为空。Protobuf 请求不能仅凭接口名证明对应了某一幅开屏广告画面。
- 旧版配置里的 `thirdAd` 字段本次已经为 `"0"`，所以本插件不再对它重复修改。

## 实现选择

1. 对已观察到的广告控制接口，只在成功且结构符合预期时将已有布尔字段 `data.isAdShow` 从 `true` 改为 `false`，保留其他字段。对错误码、缺字段、不同类型不做修改。
2. 对已观察到的两个 TME 广告获取路径，加入 POST 和喜马拉雅 User-Agent 条件，返回 HTTP 204。没有伪造未经验证的 Protobuf 响应结构。
3. 仅声明两个精确的 MitM 主机名；没有使用全域通配符、DNS 改写或全局 IP 拦截。
4. 没有启用 JavaScript、外部脚本、运行时上报接口或外部 Mock 响应文件。

HTTP Header 条件只限制规则动作，不提供按 App 的 TLS 解密隔离。共享域名上的其他请求仍可能进入 Loon 的 MitM；相关边界在 README 中单独说明。

## 已完成的离线验证

- Node.js 内置测试共 18 项全部通过，0 失败、0 跳过，其中包含 13 组实际 jq 转换夹具。
- 使用 jq 1.8.2 执行实际插件中的 JQ 表达式；检查已有关闭状态、错误码、缺失字段、字符串/空值、不同 data 类型，以及根节点类型变化。
- 将实际插件的 URL/Header 匹配条件应用到本地 173 条抓包记录，匹配 10 条请求拦截和 1 条响应修改，其余 162 条请求不匹配。
- 抓包中识别到的 5 条登录相关请求、2 条音频资源请求、7 条支付相关请求均不匹配这两条复写。
- 对匹配的原始广告控制响应执行实际 JQ 表达式，并比较全部 JSON 字段：只有 `data.isAdShow` 从 `true` 变为 `false`。
- 公开夹具覆盖其他 App User-Agent、缺失 User-Agent、错误方法、相似域名、相似路径和非成功响应，避免将接口前缀误当完整接口。

这些验证证明离线匹配范围和 JQ 转换符合预期，不等于 Loon 原生配置解析、iOS 网络运行或客户端广告逻辑已经通过验证。静态检查没有发现本插件包含额外脚本或上报行为，也不能据此承诺所有软件、所有版本绝对安全。

## 尚未验证

- 在真实 iPhone 中导入、开启和执行这份插件。
- 冷启动/热启动开屏是否消失，是否存在缓存画面和倒计时。
- HTTP 204 后 SDK 是否选择另一广告源，或是否出现等待/重试。
- 喜马拉雅的登录、已购内容、播放、下载以及其他 App 的实际兼容性。
- 后续版本的接口、域名、字段和 User-Agent 变化。

若仍有广告，需要抓取新的出现广告的启动过程，结合实际命中记录继续缩小范围。公开反馈只使用脱敏信息。
