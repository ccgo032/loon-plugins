# 第二次抓包后的修订记录

日期：2026-11-03；喜马拉雅 iOS 9.5.22。原始抓包只在本地处理，公开记录不含账号、设备标识、请求凭证、投放素材链接或原始文件名。

## 确认的事实

- 首版仍有广播剧推广，用户已明确反馈。
- 第二份导出包含 175 条请求。广告展示接口存在替换响应，isAdShow 从 true 变成 false，因此不能再将问题归因为复写整体未启用。
- 10 条 TME 广告获取请求没有导出的上游响应头，与首版拒绝请求的行为相符；导出文件本身没有提供这些本地响应的 204 状态，不能把推断写成直接看到 204。
- mobile_switch_ios 返回 enableHttpdns 为 true；AB 配置中的 useNewSplashV3 对应开关为字符串 true。
- 两条 firework-portal/v12/sync 返回自营弹屏计划，含明确的广告位、图片推广、视频推广、广播剧相关装扮推广及信息填写表单。首版没有处理该接口。
- 抓包未提供屏幕画面与某条请求的直接关联。无法确认某个计划就是用户看到的那一幅开屏画面，也不能排除本地缓存或未解密的投放链路。

## v2 修改及边界

保留首版的精准广告开关和 TME 请求处理；新增自营弹屏过滤并同步清除被删除计划的位置引用；保留信息填写表单和不相关字段。广告域名采用精确 DOMAIN 拒绝，不需要为它们开启 MitM。

将观察到的 HTTPDNS 布尔开关关闭，目的是让 App 尽量使用系统解析；这不保证清除既有解析缓存。对特定新版开屏实验 opt-out 是基于字段语义的实现推断，尚未验证客户端是否遵循、何时生效或是否回退到其他广告源。没有修改所有 AB 测试，也没有将第三方 DNS 服务 IP 全局封锁。

## 验证

- Node 测试 20 项通过，0 失败、0 跳过；包含实际 jq 执行。
- 对第二份抓包回放：10 条请求匹配拦截，5 条响应匹配处理，160 条不匹配。
- 两条弹屏响应分别删除 1 个和 15 个广告/视觉推广计划，引用同步移除；信息填写计划保留。
- 逐字段比对实际响应，修改仅限预期字段、目标计划及对应引用；签名等其余字段原样保留。
- 5 条登录与 7 条支付相关请求未匹配。实际手机的登录、播放、下载与开屏效果还没有验证。
- 发布前对两份抓包中的敏感值执行本地比对；原始抓包及真实响应未进入公开测试夹具。
